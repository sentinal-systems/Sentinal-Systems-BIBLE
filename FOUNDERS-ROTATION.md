# The Founder's Rotation — R&D / Product / Housekeeping cycles

You can't have a product-focused day if you haven't put in the R&D
hours to build the underlying tech first — and you won't have a
functional product for long if you don't step back for housekeeping
to secure the foundation.

## The three modes

```
              THE FOUNDER'S ROTATION
        ┌───────────┬───────────┬───────────┐
        ▼           ▼           ▼           │
   R&D DAYS    PRODUCT DAYS   HOUSEKEEPING DAYS
   break new   package +      align docs,
   ground:     polish +       harden, test,
   hooks,      ship what      repay debt
   math,       exists
   proofs
```

- **R&D** — break runtime hooks, write the DSP math, prove the thing
  that doesn't exist yet.
- **Product** — package builds, polish the interface, ship the
  update. Executes on what R&D proved.
- **Housekeeping** — align docs to code, harden memory, expand test
  coverage, repay debt before it locks the wheels.

## The failure modes

- **R&D forever** — an endless pile of insane proofs of concept that
  never ship.
- **Product forever** — the stack stagnates; eventually you're
  polishing a chassis that's a generation old.
- **No housekeeping** — technical debt compounds until the whole
  enterprise can't move. Docs drift from code, claims become rumors.

## The rules

1. **Parts of days count.** A rotation isn't a calendar block — an
   hour of housekeeping before shipping counts. Don't wait for a
   "housekeeping day" to fix a drifting doc.
2. **Not forced, not preset.** The mode follows the work, not a
   schedule. You don't do R&D because it's Tuesday; you do it because
   the product lane needs a thing that doesn't exist.
3. **Know which mode you're in.** The sin isn't being in a mode —
   it's doing product polish while calling it R&D, or gold-plating
   internals while calling it shipping.
4. **Housekeeping IS shipping prep.** Tightening docs and mapping the
   binary protocol isn't procrastination — it's what lets the next
   product window execute cleanly instead of guessing.
